CONCEPTS ALREADY TAUGHT (user has confirmed understanding)
===========================================================
- Bits/bytes: 8 bits = 1 byte = value 0-255.
- Hex notation: base 16, two hex digits = one byte. \x89 = 0x89 = 137.
- ASCII: byte-value-to-character lookup table (e.g. 80='P', 78='N', 71='G').
- The PNG 8-byte signature \x89PNG\r\n\x1a\n and WHY each byte exists:
    byte1 \x89 (137, >127)  -> catches old 7-bit-only transfers stripping
                                the high bit
    bytes2-4 "PNG"          -> human-readable identifier
    bytes5-6 \r\n (CR LF)   -> catches text-mode line-ending translation
                                corrupting binary data (Mac=CR, Unix=LF,
                                Windows=CRLF; PNG is binary, not text)
    byte7 \x1a (26)         -> old DOS "Ctrl-Z" EOF marker; catches naive
                                DOS tools truncating at this byte / catches
                                transfer truncation
    byte8 \n                -> catches the opposite line-ending bug
- Big-endian vs little-endian: byte order for multi-byte numbers.
  Big-endian = most-significant byte first. PNG always uses big-endian.
  0x12345678 stored big-endian = bytes [12,34,56,78].
- CRC-32: a checksum "fingerprint" of a data block; recompute on read and
  compare to stored value to detect corruption (not tamper-proof, that's
  what cryptographic hashes are for). zlib.crc32() computes PNG's exact
  variant already.
- PNG chunk structure: [4-byte length][4-byte type][data][4-byte CRC]
    - length = big-endian count of DATA bytes only (not type/self/crc)
    - type = 4 ASCII bytes, e.g. b'IHDR'
    - CRC computed over (type + data) as one continuous stream, e.g.:
        crc = zlib.crc32(chunk_type)
        crc = zlib.crc32(data, crc) & 0xffffffff
- The three chunks needed for a minimal PNG:
    IHDR (13 bytes: width,height 4B each, bit_depth,color_type,compression,
          filter,interlace 1B each; for simple RGB: depth=8,color_type=2,
          rest=0)
    IDAT (zlib-compressed pixel data)
    IEND (zero-length, marks end of file)
- Scanline filtering: every row gets 1 extra leading byte saying "how was
  this row filtered" BEFORE compression. Filter 0 = None = just prepend
  0x00 to each row (always valid, simplest). Filters 1-4 (Sub/Up/Average/
  Paeth) improve compression via neighbor-byte prediction — optimization,
  not required for correctness.
- struct.pack('>I', n): converts a Python int into 4 raw bytes, big-endian
  ('>' = big-endian, 'I' = unsigned 4-byte int). Used for both the length
  field and the CRC field of a chunk.
